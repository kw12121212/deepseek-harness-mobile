## 建议顺序

以下按“日常使用收益 + 依赖面小”做源码层面的优先级判断，未经使用频率统计；只排序已经证实的差距。队列三动作已在当前工作区接入，应先由其所属会话完成交付验收，不另开重复实现。

1. **动态 commands catalog**：已有命令菜单和执行通路，先补 Host 目录、分组、搜索与正确的接受行为；覆盖每天的命令发现，也为 skills 候选复用入口。第一阶段限定 Host 目录，不承诺复刻整个 Web 插件运行时。
2. **完整 goal 查看与编辑**：已有 `/goal` 入口，围绕当前目标、编辑、暂停 / 恢复 / 清除形成单个闭环；比 schedules、jobs、终端依赖的长连接和管理状态少。先核对实际 Host 的 goal 合同，再落原生表面。
3. **输入区附件闭环**：图片 / 文件是高频移动输入需求，当前 RPC 已起步；补系统选择、预览、上传状态、失败重试和移除后才算完成。依赖上传 receipt、会话身份及发送阻断，范围比前两项大，不能只加一个附件按钮。

## 不做清单

- **桌面浮动面板、像素级拖放停靠及由此推导的多窗口工作台**：`ui-dockkit/src/engine/planner.ts:310`、`:342` 实现 floating panel / redock；手机以单页下钻和返回栈承接，不复刻桌面空间布局（此证据不等于 OS 原生多窗口）。
