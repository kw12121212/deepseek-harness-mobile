# 流式输出期间抽屉长按（OI-012 / issue #5）

2026-11-02 · Pixel 10（`57151FDCR006YV`）· 1.1.2-qa

## 现象

会话正在流式输出时，长按抽屉里的会话/工作区行（0.9–2.5 秒）弹不出操作菜单；输出结束后同一位置按住 0.9 秒正常。

## 两个成因（Codex 定位）

1. **主线程被逐字渲染占满**：每推进一个字符就执行一次全文 markdown 正则、重建 Spannable、给 `view.text` 赋值触发整段重排。长消息（几万字符的工具输出）把主线程排满，长按的 500ms 计时回调排不上队。
2. **按着的行被换掉**：抽屉每约 250ms 因 `session/list-changed` / 运行状态刷新而重建行视图，手指按着的那一版 View 被移除，Android 的长按判定随之作废。

## 修复

| 文件 | 作用 |
| --- | --- |
| `StreamingTextPolicy.kt` | 自适应步长、码点安全、只让"未完成构造"等行尾；追平预算 `MAX_CATCH_UP_MS` |
| `StreamingMarkdownCache.kt` | 缓存稳定样式前缀，只重算尾部；渐入只改 span |
| `DrawerRenderGate.kt` | 手指按下到抬起之间推迟抽屉重建，抬手后补一次 |
| `MainActivity.kt` | Choreographer 单帧调度；滚动跟随与动画清理挂到消息生命周期 |

提交：`7e28669`（修复 + 17 项新测试）、`f4ecfd6`（把追平预算从 768ms 调到 3500ms，保住逐字观感）。

## 验证

- `./gradlew :app:testDebugUnitTest --rerun` → **170 项，0 失败**
- 真机（修复包）：
  - 空闲长按工作区/会话：菜单正常，且无 Move 项（回归）——`01-running-hold.png`
  - 会话 running（后台刷新进行中）按住 1.5 秒：菜单弹出
  - **流式输出期间自动探测**：脚本回复过程中自动开抽屉、按住第一行 1.2 秒、检查菜单文字；第一次尝试即 `menu=OPEN`（`/tmp/lp-probe.log`，14:00:12），截图 `probe-menu.png`
- 用户实测：thinking / 工具调用阶段长按均正常；总结文字阶段因渲染变快来不及手动按（这也是把追平预算调到 3.5s 的原因之一）

## 备注

探针在回复流式窗口内触发，但"按下的那一刻文字是否仍在滚动"是按时间推断的，不是逐帧断言；人工复测仍以"输出中按住 1 秒"为准。
